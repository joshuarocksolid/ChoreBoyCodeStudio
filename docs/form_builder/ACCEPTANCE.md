# Form builder acceptance

Run this on a ChoreBoy with Code Studio, a PostgreSQL 9.3 database on the main unit, and two carts that can reach that database. Plan on less than an hour when the database and both carts are already on the network.

Use an invoice header table with one key column, and a lines table whose link column points at that key. Any names are fine. This checklist calls the header table the invoice table and the child table the lines table.

Each step says what you should see.

## 1. Connection

1. Open a project in Code Studio.
2. Choose `File > Settings...` and open `Connections`.
3. Click `+ Add PostgreSQL`.
4. Set the host to the main unit, the database, and the user. Leave Password on `Ask when the app starts`.
5. Click `Test`. Type the password when asked.

**Expected.** The result starts with `Connected` and includes a table count. The driver name is `psycopg` or `pg8000`.

## 2. Form from the table

1. Choose `File > New Form…`.
2. Name the form `invoice`. Leave the folder on `forms/`.
3. Click `Build a form from a table`.
4. Choose the connection. Under `Make`, choose `Record form`.
5. Tick the header columns you want on the form.
6. Tick `Include lines from` and choose the lines table.
7. Click the create button. It names the form and the field count, and it says `and lines` when lines are included.

**Expected.** `forms/invoice.ui` opens on the Design canvas. The outline lists the fields and a table view for the lines. The Data pane summary starts with `Lines from`.

## 3. A check and a total

1. Select a required header field, such as the invoice number. Open the Behavior tab.
2. Under `CHECKS`, add `Required`.
3. Select the total field. On `STATE`, set `Value` to the `sum(...)` formula in the lines hint. The hint starts with `To total the lines`.

**Expected.** The Logic pane lists the check and the value rule. The total field's `Value` row shows the formula.

## 4. Save

1. Press `Ctrl+S`.

**Expected.** `forms/ui_invoice.py` and `forms/invoice_window.py` exist. The top of `ui_invoice.py` says `Do not edit this file` and names `invoice_window.py`. Opening `ui_invoice.py` shows that same warning on a bar, with `Edit anyway`.

## 5. Preview

1. Leave `Run behavior` unticked.
2. Press `Ctrl+Shift+R`.

**Expected.** A window opens whose title starts with `Preview` and includes `invoice.ui`. The fields and the lines grid are on the page.

## 6. Try

1. Tick `Run behavior`.
2. Press `Ctrl+Shift+R` again.
3. Change a field and save the record inside the preview.

**Expected.** The strip starts with `Data:` and then says `Changes are rolled back.` The banner starts with `Try: changes to` and says the changes are rolled back. What ran includes `Saved, then rolled back`. Read the same invoice on the main unit, outside Try. The row is unchanged.

## 7. Package

1. Close Preview.
2. Choose `Run > Package Project...` and finish the wizard.

**Expected.** The package check does not report a missing or older `ui_invoice.py`, a picture file path, or a missing `cbcs_connections.py`. You get an installable package.

## 8. Two carts

1. Install the package on cart 1 and cart 2. The app lands under `/home/default/FreeCAD/Apps/`.
2. On each cart, start the app. When the password is asked, type the main unit password.
3. On cart 1, open an invoice and change a field. Save.
4. On cart 2, open the same invoice. Confirm you see cart 1's save.
5. On both carts, change the same field without saving on cart 2 first. Save cart 1. Then save cart 2.

**Expected.** Cart 2 shows `Someone else changed this invoice since you opened it.` The buttons are `Reload their version` and `Cancel`. `Keep mine and save` is absent unless you ticked `Let people keep their version on a conflict` on the Data source sheet. `Reload their version` shows the row cart 1 saved.

The word in the dialog follows the record word. A table named `invoices` uses `invoice`.
